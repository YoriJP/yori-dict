# Japanese coverage gaps use exact Evidence identity

Explanation Languages own independent Sense divisions. A Taiwanese dictionary may merge two source meanings into one Sense, while a Korean dictionary may split one source meaning into several. Comparing their Sense counts therefore cannot prove that either group is incomplete.

Yori Dict defines Expected Evidence as the exact source identifiers admitted by the current Japanese source policy. Covered Evidence is the union of identifiers cited by one Explanation Group. Only a non-empty `Expected Evidence − Covered Evidence` derived from reliable mappings is a Proven Coverage Gap. A group without reconstructable mappings has Unknown Coverage; it remains readable and is never automatically replaced as partial.

Japanese `ja-3` stores Sense-to-Evidence relationships separately so one Sense may cite any number of Evidence identifiers. The Evidence-bearing Sense records the source version, and coverage comparisons match both that version and the Evidence identifier; ordinal identifiers from different JMdict inventories are never treated as equivalent. Rebuild and production import store each proven missing identifier with its source version and derivation basis. Absence of a gap row means only “not proven partial,” never “linguistically complete.” Schema migration creates only the new storage and indexes. Existing content stays Unknown Coverage until an explicit rebuild or release import supplies exact Evidence and performs classification.

Ordinary lookup remains model-free and returns available partial content. Authenticated Enrich-on-Lookup may replace a proven-partial group using complete Source Evidence reconstructed from canonical SQLite. Every Expected Evidence identifier must appear in the accepted result. Two unanimous review passes remain required in production. One Japanese Evidence Snapshot combines the schema version, dictionary date, and JMdict inventory version used by rebuild, import, publication, and repair. Coverage decisions read gaps, snapshot metadata, and Source Evidence in one SQLite transaction, then carry that complete snapshot through authoring. Persistence rejects the repair inside its transaction if any snapshot field is no longer current. Replacement writes one Explanation Language, all of its Evidence relationships, and gap removal in one transaction; Entry identity and other languages are untouched.

Rejected, malformed, deterministically invalid, or provider-failed repair returns the existing group and leaves the gap retryable. Storage failure remains fatal. During a same-version rebuild or release import, accepted retained content replaces a proven-partial incoming group only when its exact Expected Evidence coverage is a superset of the incoming coverage. A richer incoming group therefore wins over a poorer retained group, and Evidence unrelated to the expected JMdict inventory remains Unknown Coverage. A new source version invalidates ordinal coverage claims from the previous inventory. Release publication requires the source database itself to report the classified `ja-3` schema version and a known JMdict inventory version.

An Evidence inventory is identified by both the JMdict-simplified format version and dictionary date. A daily source refresh can shift ordinal Sense identifiers without changing the format version. New Evidence-bearing Senses and gaps store both fields as a serialized pair. Retained bare format versions or missing versions are not upgraded from the container's current metadata: earlier imports may already have changed that metadata, so those groups remain Unknown Coverage. Existing gap records matched to canonical source rows can still initiate a repair from the current source; the accepted replacement records the dated identity. Publication requires both metadata fields.

Importing an older bare-version release can date its original source rows, but cannot safely date its authored coverage claims or gap rows. Those old gaps remain unclassified after import until an explicit rebuild. Rebuild release artifacts with the dated identity before rollout rather than reusing earlier PR-generated artifacts.

When a dated inventory changes, previously authored prose cannot prove coverage of its new ordinal identifiers. If no incoming group exists, the retained group remains readable with Unknown Coverage. If the rebuild supplies an incoming group, that group takes precedence over retained content whose dated Evidence no longer matches, even when the incoming group is partial. This deliberately limits the original Issue #49 promise of retaining repairs across source refreshes: preserving coverage across changed inventories requires a stable cross-version Evidence mapping that is not available here.

This rejects two alternatives. Sense-count comparison would label legitimate cross-language structure as defective. Eager replacement of all legacy groups would spend model credits, discard useful content, and rewrite Unknown Coverage without objective evidence. Gap audit and release publication are deterministic and model-free; paid bulk repair remains a separate explicitly authorized operation.
