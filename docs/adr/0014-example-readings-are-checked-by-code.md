# Example Readings are checked by code, not by a reviewer

Learners read example sentences with furigana. Yori News derived it from a morphological tokenizer, which reads compounds piece by piece (一歩 as いちほ, 光合成 as ひかりごうせい) and every day count as か. Measured against model readings on 60 Tatoeba sentences, the tokenizer was wrong in 10 of the 12 places the two disagreed. Yori Dict therefore authors an Example Reading for each served example sentence and stores it by sentence.

ADR-0008 requires generated content to pass two unanimous reviews. Example Readings are exempt. A reading pass is one low-effort call per entry; two review passes would triple its cost for a free service, and the failures that matter most are structural: segments that do not rebuild the sentence, kanji left without a kana reading, kana in a segment that the reading does not spell out where it stands (東京タワー前 read とうきょうまえ). The Deterministic Filter rejects those per sentence. A wrong kanji reading that passes the filter is possible: run through the production prompt and filter, 55 of the same 60 sentences were stored and 2 of those carried one wrong reading (その答 as こた, 狭さく as せま).

Each sentence gets one paid attempt. A rejected sentence is stored with no reading, so no later lookup pays for it again, and consumers fall back to their own furigana. Deleting those rows retries them, for example after a prompt change. Readings are keyed by sentence text, not by example row, because example rows are replaced by release imports and rebuilds while the sentence stays the same; a reading is served for every sense that carries its sentence and survives both. A release carries the table for a store bootstrapped from it, while an import into an existing store keeps that store's own readings. Readings are authored only on the authenticated enrichment path, so the calls taper off as the examples the dictionary serves are read; public lookup never authors one.
