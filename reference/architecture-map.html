Yori Dict architecture map

The compressed version: ownership, request flows, and the release loop.

Two independent published dictionaries. One model-free read path. One authenticated gap-filling path. One staging-to-release loop.

Component ownership

ComponentOwnsDoes not own

Released storesStable published Japanese or English dataRuntime mutation

Export/release codeDeterministic SQLite, JSONL, manifests, Yomitan adapterLive lookup

Read path

Request → API → canonical production database → entry or null. No model call.

Enrichment path

Auth → cheap checks → canonical/source search → headword or SKIP → second source search → author → code validation → one-word independent review → canonical write → missing examples → response.

Release loop

Canonical database → deterministic snapshot → validation → independent dictionary release → SQLite + JSONL + Yomitan v3.

Failure rules

FailureBehavior
Invalid request, SKIP, malformed candidateStop; do not regenerate
Deterministic or semantic rejectionTerminal for that candidate
Transient on-demand provider failureFlex once, then one Standard fallback
Transient bulk provider failureAt most three Flex attempts
Example failureKeep and return the accepted entry without that example
